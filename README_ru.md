# Wasmee — Движок Durable WebAssembly

Wasmee — это быстрая и безопасная среда выполнения WebAssembly (песочница) на Rust поверх Wasmtime. Она спроектирована для запуска отказоустойчивых бизнес-задач с сохранением состояния (снапшотов), обеспечивая микросекундное время запуска и встроенную фиксацию контрольных точек.

## Производительность и нагрузочное тестирование

Wasmee спроектирован для достижения максимальной скорости. Поскольку выполнение гостевого Wasm-кода происходит полностью в оперативной памяти хост-процесса, скорость работы превышает **25 000+ RPS** на одно ядро процессора.

Для выполнения Wasm-задач удаленными клиентами Wasmee использует оптимизированный протокол **Protobuf поверх HTTP/1.1**. Благодаря передаче сырых бинарных снимков состояния и логов выполнения (минуя накладные расходы на кодирование Base64 и парсинг JSON), это существенно снижает нагрузку на CPU и сетевой трафик на localhost.

В сквозных тестах под нагрузкой из 50 параллельных клиентов (включающих полное восстановление памяти, повтор лога вызовов и запись контрольных точек в in-memory хранилище) Go-клиент при работе с Rust-демоном Wasmee через Protobuf выдает **382.25 RPS** локально со средней задержкой **130.4 мс**.

### Компромиссы производительности: Durable против Stateless

Чистый вызов функции WebAssembly без сохранения состояния (stateless) в Wasmtime может превышать **100 000+ RPS** при переиспользовании одного глобального инстанса. Однако Wasmee создан для **отказоустойчивых вычислений (durable executions)**. Для достижения этой надежности Wasmee выполняет полный жизненный цикл на каждый вызов:
1. **Изолированная песочница**: Для каждой задачи создаются новые `Linker`, `Store` (с лимитами ресурсов) и инстанс модуля, исключая утечки памяти или состояния.
2. **Восстановление состояния**: Память инстанса реконструируется на основе базового снимка и дельт и копируется в выделенную память нового инстанса.
3. **Отслеживание измененных страниц**: После выполнения хост сканирует и хеширует линейную память страницами по 64 КБ, чтобы сохранить только измененные страницы памяти для записи контрольной точки (checkpoint).

Весь этот полный цикл восстановления состояния, вызова и расчёта измененных страниц укладывается в **< 40 микросекунд** на запрос, что даёт **25 000+ in-memory RPS** на одно ядро CPU. Эти накладные расходы являются необходимой ценой за гарантированную отказоустойчивость и безопасность.


### Локальный запуск нагрузочных тестов

Вы можете запустить сквозные бенчмарки локально с помощью `k6`. Исходный код тестов расположен по пути [platform/loadtest/k6/wasm_rust.js](file:///Users/user/github.com/nativebpm/platform/loadtest/k6/wasm_rust.js).

1. **Сборка и запуск демона Wasmee**:
   ```bash
   # Сборка хост-демона
   cargo build --release
   # Сборка гостевого Wasm-модуля
   cargo build --target wasm32-wasip1 --release --package wasmee-guest
   # Запуск демона на порту 8081
   ./target/release/wasmee
   ```

2. **Запуск Go-сервера бенчмарков** (слушает порт 8085 и транслирует запросы к Rust-демону по Protobuf):
   ```bash
   # Из корневого каталога воркспейса:
   go build -o connectors/wasmee/cmd/bench_server/bench_server connectors/wasmee/cmd/bench_server/main.go
   ./connectors/wasmee/cmd/bench_server/bench_server
   ```

3. **Запуск нагрузочного теста k6**:
   ```bash
   BENCH_SERVER_URL=http://127.0.0.1:8085 k6 run platform/loadtest/k6/wasm_rust.js --vus 50 --duration 10s
   ```
