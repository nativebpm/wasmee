# Wasmee — Движок Durable WebAssembly

Wasmee — это высокопроизводительная изолированная среда выполнения WebAssembly (песочница), разработанная на Rust поверх Wasmtime. Спроектирован для высокоплотных отказоустойчивых вычислений с микросекундным временем запуска и нативной поддержкой снапшотов состояния (контрольных точек).

## Производительность и нагрузочное тестирование

Wasmee спроектирован для достижения максимальной скорости выполнения. Поскольку выполнение гостевого Wasm-модуля происходит полностью в памяти (in-memory) хост-процесса, скорость работы превышает **25 000+ RPS** на одно ядро процессора.

Для выполнения Wasm-задач удаленными клиентами Wasmee использует оптимизированный протокол **Protobuf поверх HTTP/1.1**. Благодаря передаче сырых бинарных снимков состояния, дельт памяти и оплогов (минуя накладные расходы Base64-кодирования и парсинга JSON-строк), это критически снижает нагрузку на CPU и пропускную способность сети на localhost.

В условиях сквозного нагрузочного тестирования (восстановление Wasm-памяти по дельтам, реплей оплога вызовов, фиксация контрольных точек в in-memory БД и контроль версий OCC) связка Go-клиента с Rust-демоном Wasmee через Protobuf выдает **382.25 RPS** локально со средней задержкой **130.4 мс** под нагрузкой из 50 параллельных VUs.

### Компромиссы производительности: Durable против Stateless

Чистый, бесstate-вызов функции WebAssembly в Wasmtime может превышать **100 000+ RPS** при переиспользовании одного глобального инстанса. Однако Wasmee спроектирован для **durable executions (отказоустойчивых вычислений с сохранением состояния)**. Для достижения этой надежности и безопасности Wasmee при каждом вызове совершает следующие шаги:
1. **Изолированная песочница**: Для каждой задачи создаются новые `Linker`, `Store` (с лимитами) и инстанс `Instance`, исключая взаимное влияние или утечки состояния.
2. **Восстановление состояния**: Память инстанса реконструируется на основе базового снимка и дельт и копируется в выделенную память нового инстанса.
3. **Отслеживание измененных страниц**: После выполнения хост сканирует и хеширует линейную память страницами по 64 КБ, чтобы зафиксировать дельты изменений памяти для записи контрольной точки (checkpoint).

Весь этот полный цикл восстановления состояния, вызова и расчёта измененных страниц укладывается всего в **< 40 микросекунд** на запрос, что даёт **25 000+ in-memory RPS** на одно ядро CPU. Эти накладные расходы являются обоснованной платой за гарантированную отказоустойчивость, детерминированный реплей и нативную скорость.


### Локальный запуск нагрузочных тестов

Вы можете запустить сквозные бенчмарки локально с помощью `k6`. Исходный код тестов расположен по пути [platform/loadtest/k6/wasm_rust.js](file:///Users/user/github.com/nativebpm/platform/loadtest/k6/wasm_rust.js).

1. **Сборка и запуск демона Wasmee**:
   ```bash
   # Сборка хост-демона
   cargo build --release
   # Сборка гостевого Wasm-модуля
   cargo build --target wasm32-wasip1 --release --package wasmee-guest
   # Запуск демона на порту 8081
   ./target/release/wasmee
   ```

2. **Запуск Go-сервера бенчмарков** (слушает порт 8085 и транслирует запросы к Rust-демону по Protobuf):
   ```bash
   # Из корневого каталога воркспейса:
   go build -o connectors/wasmee/cmd/bench_server/bench_server connectors/wasmee/cmd/bench_server/main.go
   ./connectors/wasmee/cmd/bench_server/bench_server
   ```

3. **Запуск нагрузочного теста k6**:
   ```bash
   BENCH_SERVER_URL=http://127.0.0.1:8085 k6 run platform/loadtest/k6/wasm_rust.js --vus 50 --duration 10s
   ```
